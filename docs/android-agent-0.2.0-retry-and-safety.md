## 任务配置

| 配置 | 默认值 | 范围与含义 |
|---|---|---|
| 失败重试 | 开启 | 可关闭 |
| 重试次数 | 1 次 | 0～10 次，不含首次执行 |
| 重试间隔 | 5 分钟 | 1～1440 分钟 |
| 重试有效期 | 30 分钟 | 1～10080 分钟，从首次失败起计算；启用时不得短于间隔 |
| 单次执行时限 | 15 分钟 | 1～180 分钟 |
| 成功判据 | 空 | 可填实际成功页面可见文案，最多 80 字符 |
| 防重复按钮 | 上班打卡,下班打卡,提交,发送 | 填页面上的完整按钮文案，用逗号分隔，最多 200 字符 |

旧任务缺少新增字段时使用上述默认值。次数、时间均按任务保存。每次重试仍受总有效期限制，后续失败和执行器忙碌不会重新延长有效期。达到次数或超过有效期后，本轮停止重试。

例如可设置最多重试 3 次、间隔 5 分钟、有效期 30 分钟；成功判据应填写目标应用真正显示的成功文案。保护按钮应填写实际“上班打卡”按钮，不建议将进入页面的“打卡签到”入口设为提交按钮。

## 执行状态与提交保障

1. 启动前原子领取任务，核对任务版本、定时触发标识和重试时间；同一执行器不能同时启动两个任务。
2. 取消重试、删除或修改任务后，旧触发不能继续领取；执行中的旧版本在后续动作前停止。暂停任务不会安排自动重试。
3. 同一任务执行中再次收到正常定时事件时合并该事件，避免完成后再执行一次。单次任务只在实际领取时消费计划。
4. 可恢复失败按配置重试；主动停止、取消、权限或配置阻塞不自动重试。进程中断记入历史并保留提交保护，不盲目重放。
5. 保护按钮点击前先持久化提交检查点。模型使用简称时尽量解析页面真实完整标签，坐标或资源 ID 也根据观察到的节点解析。已有未核实提交时拒绝再次提交；长按、双击保护按钮不允许。
6. 用户核对实际业务结果后，可在任务卡片确认解除提交保护；任务执行期间不可解除。

提交检查点表示“可能已提交”，并非业务系统的成功凭证。若记录后手势失败，仍可能需要人工核对。该机制只保护可识别且已配置的按钮，不能保证所有应用、无语义自绘控件或所有业务操作的通用幂等性。

## 定位、解析与模型执行

- 保留唯一节点优先、实际屏幕尺寸和坐标校验；动作前核对当前应用、屏幕尺寸，坐标动作进一步检查交互节点布局。无可用截图时禁止猜测坐标。
- 输入必须落在可见、可用、可编辑且有焦点的输入框；不再选择第一个输入框。输入后提交必须单独发出点击，经过提交检查点。
- 同一页面连续重复同一动作超过阈值后停止，避免无限误点。
- Home 仅为导航动作，不再据此自动判定任务完成。
- Finish 必须声明 success、failed 或 blocked；成功必须有证据。配置成功判据时，还必须在新获取的页面可见文字或描述中找到对应文案，资源 ID 不算可见成功证据。
- 格式修复沿用既有机制；修复请求中的 HTTP 错误保留分类。401 等不可恢复请求错误阻塞，408、429 和服务端错误可按任务策略重试。
- 保留最近四组动作与结果，历史副本不携带 Type 输入值；当前任务、计划和 Notes 单独提供。计划使用稳定 ID，减少文本变化产生的重复条目。
- 网络请求可随停止操作取消；单次任务有总时限。共享 HTTP 连接资源，Chat 和 Responses 均传递有界历史，未启用未经验证的服务端缓存或 previous_response_id 链。
- 自定义提示词保留，追加执行协议。因此使用自定义提示词的任务也要遵循新的 Finish 和独立提交协议。

这些改动针对执行可靠性边界，不代表模型在所有页面上的视觉定位已得到真机验证。目标应用动态加载、自绘按钮和模型视觉能力仍会影响定位。

## 调度、历史与本地接口

- 定时完成结果继续只进历史，不拉起完成弹窗。
- 定时接收器遇到已有执行时不唤醒界面；唤醒页退出后再交付执行，减少页面抢占。该时序还需实际手机及厂商系统验证。
- 前台服务的本地 HTTP 端口异常不再连带终止执行服务。
- 本地接口默认绑定 127.0.0.1，可继续通过 adb 端口转发访问；默认不直接接受局域网连接。
- 任务数据异常先保留原始备份，再尝试恢复最近有效数据并提示。
- 历史记录父运行 ID、重试序号、耗时及解析详情。截图标记为解析出的目标中心；原生节点点击时不是测量到的物理触点。
- 历史读取及图片处理移出主线程；清理历史需用户确认，运行中的记录受保护。未加入自动删除历史策略。

- runtime/RunCompletionNotifier.kt：MissingPermission，通知权限静态检查。
- schedule/TaskAlarmScheduler.kt：MissingPermission，精确闹钟权限静态检查。
- automation/AppLauncher.kt：WrongConstant，参数常量检查。

这不等同于已证实发生运行故障，也不能据此承诺完全无影响；通知、闹钟权限及厂商后台限制仍须实机验证。本轮未将这些原有问题标为已修复。
