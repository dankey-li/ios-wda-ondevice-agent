# Android Agent 0.2.3：按任务配置结束后操作

日期：2026-10-29。versionName：0.2.3，versionCode：6。

## 使用方式

在任务中心新建或编辑任务，找到“任务结束后”：

| 选择 | 行为 |
|---|---|
| 保持当前页面 | 不执行额外操作，旧任务及新任务默认使用此项 |
| 返回 One Agent 任务页 | 在业务结果保存后，尝试将 One Agent 切换到前台并打开任务页 |
| 划掉目标 App 后返回 | 打开系统最近任务，尝试移除指定目标卡片，再返回任务页 |

启用返回或划卡后，可选择“仅成功后”或“成功或失败后”。手动停止、取消、中断及运行中修改／删除任务，不自动执行收尾。失败后执行的条件包含需要人工核对的阻塞结束；如需保留失败现场，请选“仅成功后”。

划卡模式还需从已安装的可启动应用列表中选择目标 App，并按手机实际最近任务界面选择向上、向左或向右划。优先尝试系统卡片提供的移除动作，仅在没有该动作时使用所选方向的手势。应用选择列表不包括 One Agent 自身；运行时也会拒绝系统桌面和 System UI。

## 执行保障

- 不调用模型执行清理，不改变原有任务动作、成功判据、重试次数或间隔。
- 业务历史、截图、任务结果与重试状态先保存，再进行收尾；收尾失败不将业务成功改为失败，也不会为成功任务新建重试。
- 收尾与启动共用执行互斥，最长约 6.5 秒，防止旧任务的返回动作覆盖新任务。
- 收尾前及关键动作前重新核对任务版本；任务已修改或删除则跳过剩余操作。
- 划卡前要求前台仍为指定目标应用，并核对安装应用名称能唯一对应指定包名。
- 仅处理能识别的系统桌面／System UI 最近任务界面；卡片依靠受支持的标题／图标节点及完整标签匹配，拒绝模糊名称、同名多张卡片和未知卡片结构。
- 必须取得合理、完整可见的卡片边界才派发操作；不翻找其他卡片，不点击“清理全部”。
- 方向选错、卡片被锁定或厂商结构不支持时，划动可能无法移除卡片。历史只记录操作派发情况，不将它宣称为强制关闭或已验证移除。
- 收尾结果独立保存在运行目录的 `post_run.txt`，可在历史详情中的“结束后操作”查看；不覆盖业务结果和截图。
- 返回请求显式选择任务 Tab，携带独立请求标识，支持连续多次返回；不显示额外完成弹窗。

## 限制

划掉最近任务卡片不保证强制结束目标 App 的全部后台进程。Android 后台启动限制可能拦截返回请求；未确认前台时会在历史注明。

当前实现采用保守识别，仅在系统暴露受支持的卡片节点时尝试操作；不保证所有厂商、分屏、工作资料或应用分身环境。没有连接手机进行本版测试，实际划卡及界面显示需要真机验收。

本次只实现结束后操作，未开发飞书接收指令功能。
