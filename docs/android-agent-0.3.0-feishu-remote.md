# Android Agent 0.3.0：飞书指令与一次性任务

日期：2026-10-29。versionName：0.3.0，versionCode：7。

## 已实现的命令

| 命令 | 用途 |
|---|---|
| `/帮助` | 查看命令和用法 |
| `/任务` | 查看前 30 个已有任务及稳定 ID，例如 T-12345678；一次性任务不在此列表 |
| `/启动 <任务ID>` | 按完整 ID 或列表中的短 ID 启动已有任务，ID 重复或不存在时拒绝猜测 |
| `/执行 <任务内容>` | 执行一次性任务，支持换行；不保存模板、不创建计划、不自动重试 |
| `/状态` | 查看当前是否正在执行及运行 ID |
| `/停止` | 停止当前执行；空闲时可取消最近执行／远程启动任务的本轮待重试 |
| `/结果` | 查询手机最近一条已结束运行的结果，包括本机手动运行 |

仅支持文本消息。必须使用明确的 `/` 前缀；普通聊天不执行，缺参数或未知命令返回用法提示。

单聊直接发送；群聊必须在允许的群里 @当前应用机器人后发送。例如：

```text
/执行
打开设置，查看当前电量，将结果反馈给我。
```

## 手机设置

1. 安装本版 APK，打开应用，确认配置页顶部显示 0.3.0（构建 7）。本版与之前使用同一 debug 签名。
2. 先确认原有模型配置、无障碍和截图正常；允许前台服务通知，并根据手机系统允许后台运行、关闭电池优化。
3. 在配置页的飞书区域填写自建应用的 App ID、App Secret。现有 Webhook 可以继续用于原有成功通知，但 Webhook 本身不能接收指令。
4. 在“飞书远程控制”区域启用开关，填写允许控制的用户 `open_id`（ou_ 开头，可多个，逗号分隔）。白名单为空不能启用。
5. 群聊可填写群 `chat_id`（oc_ 开头）；留空仅接受单聊。群里的指令还必须 @当前机器人。
6. 指令有效期默认 5 分钟，可设 1～30 分钟。手机离线期间过期的消息被忽略，不补执行。
7. 配置 `/执行` 一次性任务的独立默认值：最长执行时间（默认 15 分钟）、可选成功文案、提交保护按钮，以及结束后操作、执行条件、目标应用和划动方向。
8. 点击“保存远程设置并重新连接”。修改开关、白名单或默认值后也需要点击此按钮。它同时保存上方飞书凭证；正常模型、任务配置沿用已有逻辑。

一次性任务的结束后操作与 0.2.3 相同：保持页面／返回 One Agent 任务页／划掉指定目标卡片后返回，默认保持。已有任务始终使用各自的结束后、重试等配置。

一次性任务会短暂保留内部执行记录以复用运行领取和提交保护，任务列表不显示，结束后清除内部任务项，历史和截图保留。App 中断时保留必要状态供恢复核对，不自动重放。

## 飞书后台配置

使用企业自建应用的应用机器人，不能只配置群自定义 Webhook 机器人。

1. 开启机器人能力，并将应用可用范围包含操作者；群聊使用时将该应用机器人加入群并允许发言。
2. 申请所需应用权限并发布版本：
   - 单聊：`im:message.p2p_msg:readonly`（读取用户发给机器人的单聊消息）。
   - 群聊可选：`im:message.group_at_msg:readonly`（接收群聊中 @机器人消息）。
   - 回复消息：`im:message:send_as_bot`（以应用身份发消息）。
3. 在事件订阅中选择长连接接收，订阅“接收消息 v2.0”：`im.message.receive_v1`。若页面要求先建立连接，先在手机保存远程配置，连接建立后再回飞书保存。
4. 获取当前应用下操作者的 open_id。可从该应用实际收到的事件数据 `event.sender.sender_id.open_id` 获取；也可使用飞书 API 调试台按自己的手机号／邮箱查询（查询过程可能需要额外通讯录权限）。同一人在不同应用下 open_id 可能不同。
5. 群 ID 从该应用收到的群消息事件 `event.message.chat_id` 获取。不要把用户 ID、应用 App ID、其他应用的 open_id 混用。
6. 测试顺序建议为 `/帮助` → `/状态` → `/任务` → 无副作用的一次性查看任务 → `/停止`。

连接状态“长连接已建立”只代表网络通道已建立，不等于事件订阅、群权限和实际执行已通过验证。

## 运行与恢复规则

- 手机主动连接飞书，使用平台返回的 WSS 地址；不开放手机公网端口，不要求电脑／中转服务器常驻。
- 复用现有 App ID／App Secret，运行时读取机器人自身 open_id 验证群内 @对象；机器人身份不能确认时不接收群指令。
- 校验应用 ID、发送者白名单、会话、消息类型和创建时间。机器人消息不触发控制。
- 持久接收记录同步落盘后才确认事件；按应用 ID＋message_id 去重，记录在应用数据内保留至少 24 小时。拒绝在日志损坏或记录已满时静默重置后重新执行。
- 调度状态不确定时标记中断、通知核对，不盲目重放。卸载清数据会删除本机去重和历史记录。
- 手机忙碌时拒绝新的启动／执行，不自动排队；查询和停止仍可处理。
- 启动前尝试亮屏；手机锁定或未唤醒时返回原因，不尝试绕过系统解锁、无障碍或截图授权。
- `/启动` 通过原有原子领取、任务版本检查、成功判据、提交保护和重试策略。远程请求不绕过原执行保护。
- 已有任务如配置重试，会报告首次失败和重试安排，并跟踪父运行 ID；支持停止取消待重试。一次性任务始终不自动重试。
- 接收、启动和最终结果分别回复原会话。收尾结果可随最终结果返回；成功截图仍保留在手机历史，原有任务的飞书 Webhook 通知不改。
- 回复经持久发件箱发送，失败退避重试，最长保留 24 小时；同一会话保持发件顺序。使用固定 uuid 辅助发送去重；不承诺跨平台去重窗口的回复绝对不重复，但任何回复重试都不重做手机任务。
- 撤销用户或群授权后，尚未执行的指令拒绝执行，待发回复也不继续发送到已撤销的对象。关闭远程开关并保存会断开接收；已启动任务可在手机停止。
- 断网自动重连；手机应用被强制停止、系统冻结或尚未启动前台服务时不能保证接收。重启手机后建议先打开 One Agent 确认连接状态。
- 首版面向一台手机。不要用同一应用同时运行其他长连接消费者期待所有终端都收到相同事件；多设备路由不在本次实现范围。

## 实现与验证

采用现有 OkHttp、协程和 Android 存储，按官方 SDK 的 pbbp2.proto／长连接帧协议实现轻量适配，未直接引入整套服务端 Java SDK。包含心跳、断线重连、分片重组、有界负载与 gzip 事件处理。

- 109 项本地测试通过，0 失败、0 错误、0 跳过。
- 原有 83 项测试保留；新增 26 项覆盖命令授权、时效和群提及校验、持久去重／中断恢复、一次性执行、已有任务、忙碌拒绝、停止、重试观察、HTTP 回复去重参数、回复网络挂起时仍可停止、WebSocket 接收后确认、存储失败不提前确认、帧样例和分片边界。
- 本地 MockWebServer 验证了 HTTP 与 WebSocket 传输，不使用真实飞书凭证，不向真实会话发送测试消息。
- `testDebugUnitTest`、`assembleDebug` 通过；APK 签名校验通过，证书与旧版一致。
- lintDebug 仍有原有 4 项错误、28 项警告，无新增项；本轮没有修复或屏蔽这些旧问题。
- 未连接手机，未安装本版，未进行真实飞书账号联调、厂商系统熄屏／后台接收或真机划卡验收。以上不应标为已通过。
