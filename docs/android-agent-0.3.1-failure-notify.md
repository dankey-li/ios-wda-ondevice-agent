# Android Agent 0.3.1：任务失败飞书通知

日期：2026-10-29。versionName：0.3.1，versionCode：8。

## 本轮范围

保留 0.3.0 的任务结束后返回 One Agent／划掉指定最近任务卡片后返回、飞书启动任务列表中的已有任务、`/执行` 一次性任务及查询／停止命令。

本轮只增加失败通知。逐步图文会话、参考模式、Pi／其他 Harness 接入、标准工作流输入和新的业务状态机均暂不开发。

## 通知设置

- 在任务中心创建／编辑任务，新增“失败后飞书通知（需配置 Webhook）”开关，默认开启。
- 已有任务没有该字段时也默认开启。可按任务关闭；原有成功通知开关及默认值保持不变。
- 任务卡片显示失败通知状态。原快捷“通知”按钮明确更名为“成功通知”，只控制成功提醒，避免与失败开关混淆。
- 先在配置页保存飞书 Webhook。仅文本通知不需要 App ID／Secret；附带截图仍需要原有的应用凭证和上传图片权限。

| 结果 | 飞书卡片 |
|---|---|
| 成功（成功通知开启时） | 绿色“任务完成” |
| 本次失败，已安排自动重试 | 橙色“本次失败，等待重试”，包含重试次数和下次时间 |
| 需要人工核对，例如验证码或成功证据不明确 | 橙色“任务需要人工核对” |
| 失败且本轮无待重试 | 红色“任务失败”，包含原因和运行 ID（已启动的运行） |

- 已创建运行的失败使用返回／划卡之前保存的最后一屏截图；它用于定位失败现场，不是成功凭证。截图不可用时仍发送文字。
- 手动和定时启动时的配置／权限失败，以及计划占用后重试到期，也可以通知；未启动时没有新运行截图，不用旧截图冒充。
- 主动停止和取消不当作失败通知。
- 通知异步发送，网络或发送异常不改变任务结果，不增加业务重试，也不重新操作手机。
- Webhook 沿用既有卡片发送和文本降级路径；发送失败记录在手机日志，不承诺断网／进程终止后必达。

## 与远程指令回执的关系

飞书 `/启动` 和 `/执行` 本来就通过应用机器人向原会话报告成功／失败，继续保留持久回复发件箱和退避重发。

一次性任务不额外启用 Webhook 失败通知，避免同时向原会话和群 Webhook 重复报告。已有任务若开启失败 Webhook，原会话回执和任务 Webhook 是两个独立目的地；不需要额外群通知时可关闭该任务的失败通知开关。
